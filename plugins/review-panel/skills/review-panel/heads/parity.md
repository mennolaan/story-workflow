HEAD: peer parity (absence stance; every finding names the sibling that sets the precedent and the consequence of the omission).

Hunt what is MISSING, not what is wrong. The other heads read the diff for defective lines, so a line that was never written is invisible to them; that class is this head's whole job. Method: for every stage, endpoint, connector, prompt, option record, component or job the diff adds or changes, read the established siblings IN FULL (the other implementations of the same kind, their validators and their tests) and name each invariant a sibling enforces that this change omits.

Classes that recur, not an exhaustive list: a cache key that carries every version constant its inputs depend on; a validator plus a sanitation pass that drops a degenerate item without dropping the whole record; a path segment validated against the one shared predicate before it becomes a storage path; an endpoint that derives the user from the authenticated principal instead of trusting a raw header value; a retry and a usage meter around every paid call; a shared constant read from its one definition instead of inlined; a test that pins the behaviour the sibling's test pins.

Anchor every finding to the changed line that should carry the invariant, cite the sibling that sets the precedent as path:line, and state what a user, an operator or the bill loses when the omission bites. An omission you cannot tie to a consequence is not a finding, and neither is a difference the area README or the decision record already justifies: read those before reporting. Use "peer" as the trigger label.

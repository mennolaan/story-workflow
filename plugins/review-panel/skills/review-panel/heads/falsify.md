HEAD: falsifiability of the held-out checks (attack stance; every finding must state its trigger).

A check nobody has watched fail is an assumption. Enumerate every check the diff adds or changes: unit and integration tests, validators, pipeline steps and whether a failed test fails the step, quality gates and their thresholds, evaluation assertions, health endpoints, and the verification commands in a README or a runbook. For each one, state the mutation it exists to catch, then look for a mutation of that same class that it would still pass. Report only the checks where you can name that passing mutation.

Classes that recur: a test that asserts a fake was called instead of asserting the behaviour; an assertion on part of a record, so a wrong value or a dropped field survives; a gate whose threshold is set where the current data already sits, so no regression can breach it; a quality gate that shows red without failing anything; a test that pins a stale constant rather than the contract, so the two can drift apart; a cache-keyed path exercised only on a warm cache, so the cold path is unproven; a check whose pass and whose absence look identical in the output. Anchor each finding to the changed line that carries the check, and state what an operator concludes wrongly when it passes. Ground upstream behaviour in facts.md.

__CONTEXT__

Cover all five stances and label each finding with its stance: delivery contracts (a result acknowledged before it is durable, retries and bounds that silently drop, a cancelled or crashed job that leaves half-written state, backpressure ending in a log line); dependency-source semantics (configuration that diverges from what the pinned SDK, cloud service or model actually does, renamed or ignored keys, defaults assumed but not set, a schema the model is not actually bound to); identity, gates and harness (a client-supplied identity header trusted, a path segment that escapes its prefix, RBAC or an allowlist admitting more than claimed, tests that pass on empty or malformed input, name the mutation that should fail each check); conformance (EOL, CVE, deprecation, contradiction of the pinned docs, divergence from repo precedent, the decision record or the area README); plan and surroundings (plan or decision-record requirements the diff lacks, collisions with sibling code, open sibling pull requests listed in scope.md, recent merges to the base branch).

What NOT to flag, in addition to what the project context above excludes: a guard for a case that cannot occur (the burden is proving the case possible); a currency delta with no CVE, no EOL and no behavioural consequence; a finding whose only trigger is a principal who already holds admin over this subscription or repo; style, naming, comment wording, import order, line length; a scale limit with no named threshold and no reason this system reaches it.

Never suppressed, whatever the exclusions say: personal data or unredacted user content reaching a model call, a log line or a stored artifact; a secret written to source control, a parameter file, a pipeline variable or a log; an authentication or authorization check that can be bypassed, including a trusted client-supplied identity header; a paid path (a model call, a cloud job) that can run without an operator asking for it.

For every finding give the minimal trigger (privilege and state required) and what a user, an operator or the bill shows; cite path:line and the facts.md entry. No style findings.

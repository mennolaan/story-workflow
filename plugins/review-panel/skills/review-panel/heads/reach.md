HEAD: reachability and trust boundary (attack stance; every finding must state its trigger).

Attack one question: who can make this code run, and what does it hold while it runs. For every endpoint, job, background worker, pipeline stage, CLI flag and runbook step the diff adds or changes, name four things: the principal that can start it, the input it takes its instructions from, the least privilege that principal needs, and every credential, managed identity, secret reference and outbound call the execution context carries. Then report each place where those four disagree: an unauthenticated endpoint that starts a paid run or reads personal data; a job whose only fence is an IP allowlist that is currently empty; an identity header trusted as authorization; a service principal or managed identity holding a role wider than the step needs; a pipeline stage that can deploy from a pull request run; a manual entry point that inherits the automated one's privilege; a secret mounted for one step and readable by every step in the same context. Read in full how this repo already fences the same surface (the other endpoints and their auth handling, the deploy conditions of the CI pipeline, the role assignments and their scopes) and cite the precedent as path:line. Ground upstream behaviour in facts.md.

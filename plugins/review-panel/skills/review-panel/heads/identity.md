Attack identity and verification: find where an identity is taken from a client-supplied header or query value and used for authorization or as a storage key; where a user key or id becomes a path segment without the path predicate the repo already uses for that; where a validation covers part of a key set; where an IP allowlist, RBAC assignment or secret-store access rule admits more than its comment claims; and where a redaction, filter or gate passes on empty, absent or malformed input. Include the test harness itself: for each check the diff adds or changes, name the mutation that should fail it, and flag any test that would still pass with the behaviour removed. Every gate must have a demonstrable failure mode. Treat a path that carries personal data or unredacted user content into a prompt, a log, a URL or a stored artifact as always in scope.
